Loading Dock and admission

Everything enters through the dock, and nothing becomes registry content until every required gate has passed.

Implemented Intake, staging, gates, and the admission transaction are implemented in the published package and covered by the repository tests.

The Loading Dock

The dock is explicit: a person or command runs a scan, and the scan does the same small set of things every time.

  • Scans explicitly. There is no watcher quietly ingesting files in the background.
  • Hashes files. Content hashing gives every intake a stable identity.
  • Records intake. Each file becomes an intake record, so what arrived and when is part of the record.
  • Detects duplicates. The same content arriving twice is recognized as the same content.
  • Classifies inputs. Recognized classifications route material to the matching source staging area.
  • Routes unknown material for user input. When the dock cannot classify a file, it queues it for a person instead of guessing.

Nothing the dock touches becomes semantic content. Routing moves a file to a staging boundary or to the needs-user queue; a proposal still has to pass every gate afterwards.

The nine gates

Admission runs all nine gates and writes only if every required gate passes. Each gate returns structured pass or fail evidence rather than a bare verdict, so a rejected package carries its own findings.

GateQuestion it asks
EvidenceIs the claim actually backed by recorded evidence?
ScopeDo the scopes involved line up?
Type and unitsDo object type and units or dimensions agree?
AssumptionsAre the assumptions compatible?
Independent criticDid an independent reviewer, not the proposer or submitter, review this?
Human conceptHas the human accepted the declared concept-level semantic change?
Registry writeIs the package structurally valid and safe to write?
CollisionDoes the symbol collide with something already occupying it?
Concept layerDoes the chain go through a concept, rather than around it?

The write gate is evaluated first, because no other question is meaningful about structurally invalid input.

What happens on failure

A package that fails stays a proposal. Its findings stay attached to it and are rendered for review, so the next reader sees why it did not pass. Admission is a transaction: either the registry gains the admitted records, or it is unchanged.

A package that passes is written, and the official view is regenerated by the deterministic writer.
