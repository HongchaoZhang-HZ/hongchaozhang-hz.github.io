The semantic chain

The sidebar group Notation System documents the implemented component the repository calls the Notation Backbone.

Implemented The Notation Backbone is the grounded notation baseline in this repository, written against the Python standard library only. A separate notation-first Notation Backbone V2 package is also tracked; these pages document the Notation Backbone and make no claim about V2 behavior.

One chain, in one direction

Every project symbol has to arrive through the same chain:

source-local symbol -> evidence -> semantic concept -> project symbol

A source-local symbol is what a particular paper, dataset, or note happens to write. Evidence is the recorded material that says what that symbol means in that source. A semantic concept is the meaning itself, stated independently of any display form. A project symbol is what the project chooses to write for that concept.

Direct admission is rejected

A direct edge from a source symbol to a project symbol is inadmissible. Someone can deliberately claim one — the artifact family includes a direct-alias claim precisely so the claim can be stated and examined — but the gates reject it rather than quietly accepting the shortcut.

The rejected shortcut is the whole point of the design. “Their x is our x” is a statement about symbols. The system requires a statement about meaning, backed by evidence, before a symbol is allowed to stand for anything.

Concept identity survives display changes

Concept identity is stable, and it is not the same thing as the symbol used to display a concept. If the project later decides to write a concept differently, the concept keeps its identity, and the change is classified as a display-symbol revision rather than a change of meaning. That distinction is what invalidation is built on.
