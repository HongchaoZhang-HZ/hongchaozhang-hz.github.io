Obsidian and Herdr views

Obsidian and Herdr expose the same work from different directions. Obsidian is the durable inspection and review surface; WezTerm plus Herdr is the live dialogue and execution surface. Neither becomes a second theorem engine.

Implemented The projection contract below is implemented and test-backed. Generated views remain read-only and carry no theorem-state authority.

What the projection reads

The Obsidian projection reads the authenticated case report after execution. It does not reconstruct truth from terminal text and does not write back into A, B, C, or a human-owned Hypothesis Work Unit.

The nine generated views

  1. Project Overview states authority boundaries, links every view, explains Graph and Local Graph use, and exposes the linked Herdr entry points.
  2. Hypothesis Overview shows the catalogue, deterministic selection, and the selected Hypothesis for each formulation.
  3. Theorem Graph renders formulas, assumptions, derivations, obligations, and conclusions as exact typed Mermaid edges.
  4. Derivation Paths shows each named support path and the dynamic Hypothesis-ledger-verifier-commit sequence.
  5. Obligation Inbox separates graph obligations from authenticated verification obligations and shows their current status.
  6. Evidence and Counterexamples shows adapter outcomes, scope, certificates, and validated or dismissed witnesses.
  7. Commit Decisions shows the only decisions with mathematical force and whether the checkpoint advanced or was preserved.
  8. Revision Impact shows recorded invalidation and resume effects, or explicitly states that no revision event exists.
  9. Checkpoint and Audit Timeline projects ordered ledger events and checkpoint transitions without copying terminal scrollback.

Linked entity notes for formulations, verification obligations, and counterexamples make the Obsidian Graph exploratory. The existing Hypothesis catalogue and linked HY work unit remain the Hypothesis layer; the projection does not create replacement Hypothesis entities.

Which view answers which question

Use wikilinks for exact navigation, Local Graph for nearby reachability, Graph for exploratory reachability, and the embedded Mermaid diagrams when edge type or event order matters. That division avoids treating a force-directed Graph layout as a proof ordering.

Ownership and determinism

  • The publisher accepts only a vault containing .obsidian and requires a vault-relative output root.
  • It writes one generated case directory and refuses to replace a directory without its ownership manifest.
  • Regeneration stages a complete directory, swaps it with the owned projection, and restores the prior directory if the swap fails.
  • The manifest contains no timestamp, so identical inputs produce identical files.
  • Runtime projection includes only role, mode, session, workspace, tab, pane, and agent identifiers. It excludes terminal logs, chat history, hidden reasoning, and runtime timestamps.

Where human decisions live

In Obsidian, the human browses local reachability, inspects paths and evidence, reviews open obligations, and follows links to the human-owned Hypothesis, Handoff, and Review index. Generated files are not decision forms: a durable human decision stays in the existing Review and Handoff workflow.

In WezTerm plus Herdr, the human enters the Dialogue pane, and the Facilitator may delegate bounded work to the Worker and recover status through deterministic status panes. The Project Overview shows runtime identifiers and the existing manage and open commands, but generation never attaches a Herdr client.

The combined interface is one system with two surfaces: Obsidian explains and connects durable state, and WezTerm plus Herdr performs live interaction. The authenticated report and the commit checkpoint remain the source of mathematical status.
