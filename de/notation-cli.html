CLI entry command

The Notation Backbone exposes its workflow as explicit commands. Start from the help output.

Implemented The entry point below belongs to the published, standard-library-only implementation. This page makes no claim about any package that is not in this repository.

Entry point

python3 code/notation-backbone/notation.py --help

The help output lists the available subcommands. Every step of the workflow is an explicit command: nothing runs as a background daemon, and nothing is admitted as a side effect of putting a file somewhere.

The shape of the workflow

The commands follow the same order as the concepts in these pages:

  1. Create the workspace layout. The numbered directories described in Architecture and roles are created explicitly.
  2. Scan the dock. Incoming files are hashed, recorded, classified, and routed, as described in Loading Dock and admission.
  3. Submit a proposal. Staged files are bundled into a proposal package. Staging is not admission.
  4. Review it independently. A decision is appended by someone other than the proposer and submitter.
  5. Run admission. Every gate runs, and the registry is written only on success.
  6. Read the state, snapshot it, or reproduce a case. Status reports the workspace, a snapshot hashes the concept, notation, and mapping layers, and a manifest-driven case can be reproduced in a clean target.

Run the help command first. It is the authoritative list of subcommands and options for the version you have checked out; this page describes what those commands are for, not a substitute for their exact usage text.
