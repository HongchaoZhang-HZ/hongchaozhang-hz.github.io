Workflow replay

One Hypothesis moving from a proposal to a completed, human-owned TODO, in seven parts.

Draft design The replay illustrates the draft Hypothesis Work Unit design. Treat it as a walkthrough of intended interaction, not as a performance claim or a product demonstration.

Current capability The published Hypothesis Work Unit runtime and workflow replay use the Codex App as Manager. That is the implemented role mapping this page describes.

Next-stage target The bilingual user guide proposes Codex or Claude as the one Selected Manager, the single Active Manager of a Project, reached through shared Manager Adapters and a durable Handoff. That selection is a next-stage target, not implemented current Hypothesis behavior.

The seven parts

  1. Propose the Hypothesis. In Codex App, the user proposes a Hypothesis with an exact ID and title. The ID is chosen up front because every later path, link, and status projection resolves against it.
  2. The Manager creates the unit and reports. The Manager creates the work unit and reports the durable paths, the Herdr workspace, the Dialogue role, the Worker role, and the resume command. After this frame, nothing important is held only in the conversation.
  3. A short bounded question. In Herdr Dialogue, the Facilitator asks one short bounded question, while Dialogue Status shows the shared state and the Human TODO beside it. The question is small enough to answer without opening a document.
  4. The human answers in natural language. The Facilitator records the boundary that the answer establishes and keeps reversible work inside Dialogue instead of escalating it.
  5. The Worker waits for delegation. A separate Worker tab shows Claude Code in Auto Mode waiting for bounded delegation and reading durable state. Execution is a distinct surface, not a side effect of the conversation.
  6. The answer becomes durable, and the human completes the TODO. Dialogue Status shows the answer recorded in Handoff.md. An intentional Command-click completes the human-owned TODO item while visible completion history is preserved.
  7. Obsidian shows the same durable state. The vault shows the same Hypothesis, the same Handoff, the Review area, and the completed Human TODO. The tools and panes were views; the files are the record.

What to notice

  • The exact ID appears in frame one and never changes.
  • Each frame ends with durable state that could survive losing every open window.
  • The only completion of human-owned work is done by the human, in frame six.
  • Dialogue and Worker stay separate throughout, exactly as Roles and surfaces describes.

To reproduce the artifact side of this replay locally, see CLI entry commands. Artifact rendering needs only Python; the live panes in the replay additionally need Herdr and the configured agent runtimes.
