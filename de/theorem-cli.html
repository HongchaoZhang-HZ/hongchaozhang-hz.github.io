CLI entry commands

Theorem Derivation is data-driven: the commands run a case bundle and report what happened. Start from the help output.

Implemented The commands below belong to the published package, which uses the Python standard library only. No solver is installed or invoked by this repository.

Entry point

python3 code/theorem-derivation/derive.py --help

The help output is the authoritative list of subcommands and options for the version you have checked out.

List the verifier adapters

Ask which adapters the default verifier plane registers, before trusting any of them with a question.

python3 code/theorem-derivation/derive.py adapters

Inspect Hypothesis discovery

Print the catalogue a case bundle names, together with the ranking of each declared discovery context. Discovery is metadata driven, records every candidate with its reasons, and fails closed on zero matches and on an unresolved tie.

python3 code/theorem-derivation/derive.py hypotheses --case examples/theorem-derivation/lp-coverage/case.json

Run a case

python3 code/theorem-derivation/derive.py run --case examples/theorem-derivation/lp-coverage/case.json

run accepts --format json and --output PATH for a stored report. Reports carry no timestamps, so the same bundle always produces the same report_hash.

Publish the read-only Obsidian views

Publication runs the case and writes one owned directory under Theorem Derivation Views. Both the vault and the linked Hypothesis unit are explicit arguments.

python3 code/theorem-derivation/derive.py obsidian \
  --case examples/theorem-derivation/lp-coverage/case.json \
  --vault "/path/to/ProjectVault" \
  --hypothesis-unit "Hypotheses/HY-001"

It consumes the existing Hypothesis catalogue and linked HY work unit instead of creating a parallel Hypothesis system. Regeneration refuses an unowned destination and never edits a linked HY definition, Handoff, or Review. See Obsidian and Herdr views for the full projection contract.

Run the tests

PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_theorem_derivation*.py' -v

The example case data lives in examples/theorem-derivation/.

What these commands do not do

  • They do not install or invoke a solver. The bundled finite-domain adapter enumerates declared finite domains, and the external SMT seam reports unsupported when no runner is configured.
  • They do not create or update a Hypothesis Work Unit. de.py propose does not create a theorem case bundle, a completed Review packet does not submit a theorem transition, and a theorem outcome does not rewrite a Hypothesis status.
  • They do not exchange records with the Notation packages. No adapter imports a Notation V1 snapshot into a theorem case, and an advanced outcome is not exported into the Loading Dock.

Until those adapters exist, use one identifier convention across the case files and review the correspondence through the generated notes. That is a human discipline, not a checked invariant, and the architecture diagrams draw it as a dashed arrow for exactly that reason.
